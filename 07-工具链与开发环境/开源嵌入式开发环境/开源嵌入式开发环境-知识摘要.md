## CMake
- **ex1**
  ![[99-附件/开源嵌入式开发环境/259bff9acaa2630865309b9258f5567443ee7f2b3ff04b34abce19a4c0dc63ed.png]]
  - **cmake_minimum_required**
    写在最开头：声明本工程要求的最低 CMake 版本。若当前 CMake 版本低于该值，配置阶段直接报错退出。
    ex1 中写作 cmake_minimum_required(VERSION 3.16)。
  - **project**
    定义工程：必须在 cmake_minimum_required 之后、其他命令之前。
    MyfirstCmakeProject：工程名，同时定义变量 ${PROJECT_NAME}。
    LANGUAGES C：只启用 C 语言。不写的话默认启用 C 和 C++，配置阶段会多花时间检测 C++ 编译器。
    VERSION 1.0：版本号，自动生成 ${PROJECT_VERSION}、${MyfirstCmakeProject_VERSION}、${PROJECT_VERSION_MAJOR}(1)、${PROJECT_VERSION_MINOR}(0)。
  - **set**
    赋值：用法为 set(变量 值)。
    位置要求：CMAKE_C_STANDARD / CMAKE_C_STANDARD_REQUIRED 必须在 add_library / add_executable 之前，因为它们只对新创建的目标生效；而 CMAKE_EXPORT_COMPILE_COMMANDS 是全局变量，写在顶层任意位置都行。
    - CMAKE_C_STANDARD 99 → 编译时加 -std=c99，可取 90/99/11/17/23。
      CMAKE_C_STANDARD_REQUIRED ON → 必须支持，编译器不支持就报错；若为 OFF（默认），编译器不支持时会悄悄退回老标准，容易埋坑。
    - set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
      在 build/ 下生成 compile_commands.json，里面记录了每个源文件实际使用的完整编译命令（含所有 -I、-D）。
      clangd / VSCode 靠它提供准确的代码跳转、补全和错误提示；没有它，编辑器只能瞎猜头文件在哪。
  - **add_library**
    创建静态库：add_library(目标名 源文件...) → 把 mylib.c 编译并打包成静态库 libMyLib.a（MinGW/GCC 下是 .a，MSVC 下是 .lib，arm-none-eabi-gcc 下同 GCC 为 .a）。
    没写 STATIC/SHARED 时默认是 STATIC（受变量 BUILD_SHARED_LIBS 控制）。MyLib 是逻辑目标名，后续 target_* 命令都用它引用。
  - **target_include_directories**
    头文件搜索路径（注意拼写是 directories，不是 directions）。
    ${CMAKE_CURRENT_SOURCE_DIR} = 当前 CMakeLists.txt 所在目录的绝对路径；用绝对路径可避免相对路径在多级目录下出错。
    对比：${CMAKE_SOURCE_DIR} 是最顶层的目录，单层工程两者相同，多层工程要区分。
    - **关键字对比**
      ![[99-附件/开源嵌入式开发环境/1a52416fb3e9d1e37e2f940134989fb37dba501b689cfc74de6b331f13978485.png]]
      - **PRIVATE：仅自己编译时用，不传给链接我的下游目标。**
      - INTERFACE：自己不用，纯传给下游（典型如纯头文件库）。
      - **PUBLIC：自己编译用，链接我的目标也用（两者都用）。**
  - **add_executable**
    创建可执行文件：add_executable(目标名 源文件...) → 生成 MyCMakeProject.exe。
    注意：main.c 里写了 #include "mylib.h"，但这里没有加 -I01/inc——靠的就是下一步 target_link_libraries 从 MyLib 继承过来的头文件路径。
  - **target_link_libraries**
    链接库：把 MyLib 链接进 MyCMakeProject，一步做了两件事——
    连库：最终链接命令里加上 libMyLib.a。
    继承 PUBLIC 属性：自动把 MyLib 的 INTERFACE_INCLUDE_DIRECTORIES（即 01/inc）加到 MyCMakeProject 的编译选项里。
- **ex2**
- 执行指令（也可以使用 VSCode 的 CMake Tools 扩展图形化操作）
  - **cmake -S . -B build -G Ninja**
    - -S . 指定源码目录（source directory），"." 代表当前目录。
    - -B build 指定构建目录（build directory）。
      - 官方写作 -B <path-to-build>（Explicitly specify a build directory），并没有 --build-directory 这个长选项。
        特征：
        目录不存在时会自动创建——第一次跑 cmake -S . -B build -G Ninja，build/ 就是 CMake 建的。
        值是路径，相对于当前工作目录；写 -B build 就是 ./build。
        名字完全自定，叫 build 纯粹是社区惯例，是「习惯」不是「规矩」。
    - **-G Ninja 指定生成器（generator）。**
      - generator 决定 CMake 生成哪种构建文件：Ninja → build.ninja；Unix Makefiles → Makefile；Visual Studio → .sln 工程。
        换生成器只需改 -G 的值，后续 cmake --build 会自动识别。
  - **cmake --build build**
    - **--build 开始编译**
      - cmake --build 会读取 build/CMakeCache.txt，看里面记录的生成器是谁，然后调用对应的工具。所以换生成器不用改这条命令——这就是它存在的全部理由：生成器无关（generator-agnostic）。
    - **build 编译的目录**
  - **.\build\MyCMakeProject.exe**
## 环境组成：VSCode + CMake + Ninja + arm-gcc + OpenOCD + clangd
![[99-附件/开源嵌入式开发环境/6b6101d45eef18d667eb85743e47e2c3e8339a34055ac152fefe0de3e34a1874.png]]
- **编辑器 + 语言服务**
  - **VSCode**
    微软的免费代码编辑器，本方案里当 IDE 用：装好 C/C++、CMake Tools 扩展后，可在编辑器内完成配置、编译、烧录、调试。
  - **clangd**
    C/C++ 语言服务器（LSP）。给 VSCode / Vim / CLion 提供补全、跳转定义、查找引用、错误提示、格式化。
    依赖 CMake 导出的 compile_commands.json 才能准确工作——这正是 ex1 里开启 CMAKE_EXPORT_COMPILE_COMMANDS 的原因。
    简单理解：写代码时的智能提示后端。
- **构建系统**
  - **CMake**
    跨平台构建系统生成器。读取 CMakeLists.txt，生成 Ninja、Makefile 或 IDE 工程文件；负责管理源码、头文件、编译选项、链接脚本、库依赖、交叉编译配置。
    简单理解：项目构建配置工具。
  - **Ninja**
    小型、高速的构建工具。读取 CMake 生成的 build.ninja，按依赖关系调用编译器和链接器。
    简单理解：真正执行编译链接的构建器。
- **编译器 / 工具链**
  - **arm-gcc**
    通常指 ARM 交叉编译工具链，如 arm-none-eabi-gcc。把 C/C++/汇编编译链接成 ARM 程序，生成 .elf、.hex、.bin，工具链内含 gcc、ld、objcopy、gdb 等。
    简单理解：真正的 ARM 编译器 / 工具链。
- **调试 / 烧录**
  - **OpenOCD**
    Open On-Chip Debugger，开源片上调试 / 烧录工具。通过 JTAG/SWD 连接 MCU，提供 GDB Server，支持烧写 Flash、断点、单步、读寄存器 / 内存。
    简单理解：下载、烧录、调试目标板。
