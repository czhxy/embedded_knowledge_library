# C 语言指针辨析

## 指针数组 数组指针
- **指针数组：本质是数组。实质是数组中的每个元素都是一个指针。**
  一般形式为：int *p[5]
  - 使用场景：存储多个字符串。如星期数组，数组的每个元素可以代表一天，如week[0]="monday"。
  - 关键辨析：[]优先级高于*，p先与[5]结合成数组，数组元素类型为int*
- **数组指针：本质是指针。实质是指向数组的指针。**
  一般形式为：int (*p)[5]
  - 使用场景：一般配合二维数组使用。如 int a[3][4]; int (*p)[4] = a; 则 p+1 跳过一整行
  - 关键辨析：()改变优先级，p先与*结合成指针，指针指向int[5]数组
- **sizeof差异：**
  指针数组 sizeof(p) = 元素个数 × sizeof(指针) = 5×8=40（64位）
  数组指针 sizeof(p) = 一个指针的大小 = 8（64位）
## 函数指针 指针函数
- **指针函数：本质是函数。返回值是指针。**
  一般形式：int *func(int a)
  - 使用场景1：malloc/calloc等库函数，返回分配的内存地址
  - **使用场景2：返回静态局部变量地址，保证返回后内存仍有效**
  - 注意事项：绝不能返回局部非静态变量的地址，函数返回后栈内存已释放
- **函数指针：本质是指针。**
  一般形式：int (*f)(int, int)
  - typedef简化声明：typedef int (*cmp_t)(int, int);
    之后可用 cmp_t f = myFunc;
  - 回调函数：typedef void (*callback_t)(void);
    回调函数实现底层解耦——底层中断中调用回调函数，更改行为只需修改回调函数内容，不需要改动中断代码。
    典型场景：定时器回调、信号处理、事件驱动
  - **函数指针数组（跳转表）：**
    void (*handlers[])(void) = {func1, func2, func3};
    handlers[state](); // 根据状态跳转不同函数
    典型场景：状态机、菜单系统
## 指针常量与常量指针
- **常量指针（指向常量的指针）：**
  const int *p;  或  int const *p;
  指针指向的内容不可改(*p只读)，但指针本身可以指向别处
  - **代码示例：**
    const int a = 10;
    const int *p = &a;
    *p = 20; // 编译错误！
    p = &b;  // 正确
- **指针常量（指针本身是常量）：**
  int * const p;
  指针指向不可改（p不能重新赋值），但指向的内容可以修改
  - **代码示例：**
    int a = 10;
    int * const p = &a;
    *p = 20;  // 正确，可以改内容
    p = &b;   // 编译错误！
- **常量指针常量（两者都是常量）：**
  const int * const p;
  指针指向不可改，指向的内容也不可改
  - **记忆技巧：看const在*的哪一边。**
    const在*左边 → 修饰 *p（内容只读）
    const在*右边 → 修饰 p（指针只读）
    两边都有 → 都只读
## 野指针与悬空指针
- **野指针：未初始化的指针，指向随机的未知地址。**
  int *p; *p = 10; // 危险！p的值是随机的
  - **产生原因：**
    1. 定义指针时未初始化
    2. 指针越界访问后指向了不确定区域
- **悬空指针：指向已释放内存的指针。**
  free(p)后p仍然保存原地址，但该地址已归还给系统
  - **产生原因：**
    1. free后未置NULL
    2. 返回了局部变量的地址
    3. 指向的内存已被其他代码回收
- **防范措施：**
  1. 定义指针时初始化为 NULL
  2. free(p) 后立即执行 p = NULL
  3. 使用指针前判断 p != NULL
  4. 不返回局部非静态变量的地址
## 字符数组 字符指针
- **char s[] = "abc"：**
  栈上的字符数组，s是数组名（地址常量，不可重新赋值），数组内容可修改
- **char *p = "abc"：**
  p是指针，指向常量区的字符串字面量。内容不可修改——*p='A'会导致段错误
- **sizeof差异：**
  sizeof(s) = 4（含末尾\0）
  sizeof(p) = 指针大小（32位4字节 / 64位8字节）
- **数组名退化：**
  作为函数参数传递时，数组名退化为指针，此时sizeof失效。
  void func(char s[]) 等价于 void func(char *s)
## 多级指针
- **二级指针：int **p;**
  p是一个指针，指向另一个int*指针
- **使用场景1：函数中修改一级指针**
  void alloc(int **p) { *p = malloc(100); }
  调用：int *ptr; alloc(&ptr);
- **使用场景2：main函数的argv**
  int main(int argc, char **argv)
  argv是指向字符串数组的二级指针
- **注意：多级指针不等于多维数组。**
  int **p 不一定可以指向 int a[3][4]——
  这是因为a[3][4]是指向int[4]的数组指针，不是指向int*的指针
## 指针运算
- **p + 1：按指向类型大小步进。**
  int *p中p+1跳sizeof(int)=4字节
  double *p中p+1跳sizeof(double)=8字节
  不是简单的地址+1
- **指针相减：p2 - p1**
  得到两者之间的元素个数差值（不是字节数差）
  前提：两者必须指向同一数组（或同一连续内存块）
- ***p++ 与 *++p 辨析：**
  *p++：先取*p的值，然后p自增（后缀++，先用后加）
  *++p：先p自增，然后取*p的值（前缀++，先加后用）
- **指针比较（<、>、==）：**
  同一数组内的指针比较有意义（地址大的在后）
  不同数组的指针比较结果是未定义行为（不要这么做）
## void指针
- **void* 是泛型指针，可以接收任意类型的指针地址：**
  int a = 10; void *p = &a; // 合法
- 限制1：不能解引用。*vptr 是非法的，因为编译器不知道指向的类型大小
- 限制2：不能做算术运算。vptr+1 是非法的，不知道步进多大
- **使用场景：**
  1. malloc返回void*，由调用者决定使用的类型
  2. 回调函数的上下文参数（如pthread_create的void* arg）
  3. 通用数据结构的存储（存放任意类型）
## 指针与动态内存
- **malloc(size_t size)：**
  分配size字节未初始化内存，返回void*。
  int *p = (int*)malloc(10 * sizeof(int));
- **calloc(n, size)：**
  分配n个大小为size的元素，并将内存清零。
  int *p = (int*)calloc(10, sizeof(int));
- **realloc(ptr, new_size)：**
  重新调整已分配内存的大小，可能移动内存位置。
  ptr = realloc(ptr, new_size);
- **free(ptr)：**
  释放之前分配的内存。
  free(p); p = NULL; // 释放后立即置NULL
- **常见错误：**
  1. 忘记free导致内存泄漏
  2. free后继续使用（悬空指针）
  3. 多次free同一指针
  4. 内存越界访问（分配10个却访问第11个）
- **二维数组动态分配：**
  // 不连续方式：
  int **p = malloc(3*sizeof(int*));
  for(i=0;i<3;i++) p[i]=malloc(4*sizeof(int));
  // 连续方式：
  int (*q)[4] = malloc(3*4*sizeof(int));
## 结构体指针与链表
- **结构体指针用 -> 访问成员：**
  struct Point { int x; int y; };
  struct Point *p = &pt;
  p->x = 10;  // 等价于 (*p).x = 10;
- **自引用结构体（链表节点）：**
  typedef struct Node {
      int data;
      struct Node *next;  // 注意：此处还不能用Node*
  } Node;
- **为什么必须用struct Node*而不是Node*？**
  typedef完成之前，Node类型名还不存在，编译器只认识struct Node
- **链表基本操作：**
  1. 头插法：新节点next指向原head，更新head
  2. 尾插法：遍历到尾部，tail->next指向新节点
  3. 删除节点：前驱节点的next指向被删节点的next
