## 枚举
- **主机读取从设备的各种描述符信息，以此选择合适的驱动程序**
- USB 枚举过程（图 2-5）：主机依次完成设备接入、速度检测、复位、获取设备 / 配置 / 字符串描述符、设置配置，最后进入正常通信
  ![[99-附件/USB/18e6vofpo5elcdti8okrssbm02.png]]
- **枚举流程**
  枚举 = 主机主导的状态机 + 端点 0 控制传输 + SETUP 请求序列。
  - **1. USB 设备接入**
  - **2. 检测 USB 设备速度**
    - **高速和低速模式识别的原理**
      - 主机端DP DM都有15k的下拉电阻，从机端dp接一个3v3 1.5k的上拉电阻连上后，主机端dp识别3v，就认为有一个全速的从机设备连接了。从机端dm接一个3v3 1.5k的上拉电阻连上后，主机端dm识别3v，就认为有一个低速的从机设备连接了
        - USB 插入与速度检测（图 2-4）：主机端 D+、D- 各有 15kΩ 下拉；全速 / 高速设备在 D+ 接 1.5kΩ 上拉到 3.3V，低速设备在 D- 上拉
          ![[99-附件/USB/56r46rvu7qsnlvmi68hts9cbka.png]]
        - 高速（High Speed）识别：设备接入时先按全速方式在 D+ 上拉 1.5kΩ，主机先识别为全速设备；复位期间双方通过 chirp K / chirp J 握手确认高速能力，握手成功后设备断开上拉并切换到高速模式
  - **3. 复位设备**
  - **4. 获取设备描述符**
    - 设备描述符字段定义（表 2-2 上半）：bLength、bDescriptorType、bcdUSB、bDeviceClass/SubClass/Protocol、bMaxPacketSize0、idVendor 等
      ![[99-附件/USB/15crj3hffv6eq97pq6uvp9fgd1.png]]
      - **VID**
        - VID	Vendor ID，厂商 ID	16 位	由 USB-IF 分配给厂商	标识设备制造商/厂商
        - **VID 由 USB-IF 管理，厂商通常需要申请或购买。**
      - **PID**
        - PID	Product ID，产品 ID	16 位	由厂商自己分配	标识该厂商下的具体产品型号
        - PID 由厂商自行分配，不需要 USB-IF 单独分配，但同一厂商内应保持唯一。
    - 设备描述符字段定义（表 2-2 下半）：iManufacturer、iProduct、iSerialNumber、bNumConfigurations
      ![[99-附件/USB/6cnvg5u206t38lhk7ipfqn3jah.png]]

  - **6. 获取配置描述符**

      主要信息是配置描述符的长度（包括接口描述符、端点描述符和其他类描述符等），接口的数量、 USB 供电和唤醒方式以及此设备工作所需的最大电流

    - **特殊类型描述符**
      - **特殊类描述符**
        • CDC 类描述符
        • HID 类描述符
        • MassStorage 类描述符
        • 音频类描述符
        • 报告描述符（针对 HID 设备）
  - **7. 获取字符串描述符**
    - 语言 ID 字符串描述符（表 2-6）：bLength、bDescriptorType、LangID
      ![[99-附件/USB/6rdjuljtu5eetibd02jbc23i82.png]]
  - **8. 枚举完成**
- USB 中的 SETUP 请求（更准确叫 Setup Packet / Setup Data）是控制传输（Control Transfer）的第一阶段，由主机发给设备，固定为 8 字节。它告诉设备“要执行什么请求”，例如读描述符、设置地址、设置配置、HID 类请求等。所有 USB 设备都必须在端点 0 支持控制传输，所以 SETUP 是 USB 枚举和配置的核心。
  SETUP 请求主要是对设备描述符、配置描述符、字符串描述符、接口描述符和端点描述符等的请求。
  - **SETUP 请求只出现在控制传输中。**
    它由主机发起，设备不能主动发 SETUP。
    SETUP 数据永远是主机 → 设备。
    方向位只决定后续 DATA 阶段的方向。
    标准请求由 USB 核心处理；类请求由类驱动处理；厂商请求由设备固件自定义处理。
    如果设备不支持某个请求，通常在数据阶段或状态阶段返回 STALL。
## 协议层
- USB 协议组成（图 2-11）：一次传输由 SOP、SYNC、Packet Content、EOP 四部分组成
  ![[99-附件/USB/3ltb9di5aia28schia0vi05mo5.png]]
- USB 协议由 SOP， SYNC， Packet Content 和 EOP 组成。
  • SOP（Start of packet）：从 IDLE 状态(J 状态)切换到 K 状态
  • SYNC（synchronization field）： 3 个重复的 KJ 状态切换，后跟随 2 个位时间的 K 状态
  • Packet Content：包的组成
  • EOP（End of packet）：持续 2 个位时间的 SE0 信号，后跟随 1 个位时间的 J 状态
  - **不同速度下JK状态对应差分值**
    ![[99-附件/USB/14cuhg1fri62nsr5aen8ab0sb8.png]]
  - **Packet Content**
    - Packet Content 的字段构成：PID、地址、帧号、数据、CRC
      ![[99-附件/USB/3f00jq23hdmma3lngb59bj71vq.png]]
      - **PID域**
        - PID 格式（图 2-13）：低 4 位为类型字段，高 4 位为低 4 位的按位取反校验
          ![[99-附件/USB/7b6hlpr2ggmsaho32gnof8vmvf.png]]
        - PID（Packet Identifier），数据包标识符（PID）紧随每个 USB 数据包的 SYNC 字段之后。 PID 由四位数据包类型字段和四位校验字段组成， PID 用于指示数据包的类型，并由此推断出数据包的格式及其采用的错误检测机制。 PID 的 4 位校验字段可确保 PID 本身的可靠解码，从而正确解析数据包的其余内容。该校验字段是通过对数据包类型字段取反码（按位取反）生成的。如果这 4 位 PID 校验位未能与对应数据包标识位形成互补关系，则判定存在 PID 错误。
          主机和所有函数必须对所有接收到的 PID 字段执行完整的解码。任何带有失败校验字段或解码为未定义值的 PID 都被认为已损坏，并且它以及数据包的其余部分都被数据包接收器忽略。如果一个函数接收到它不支持的事务类型或方向的有效 PID，则该函数不得响应。例如，仅 IN 端点必须忽略 OUT 令牌。
      - **帧号/地址**
        - **地址域**
          - 地址域中的设备地址（图 2-14）：7 位，Addr0 ~ Addr6，LSB 在前
            ![[99-附件/USB/44rcv35bg24skru6gkt7nfq286.png]]
          - 地址域中的端点地址（图 2-15）：4 位，Endp0 ~ Endp3，LSB 在前
            ![[99-附件/USB/56te4d76vji4itdcpangtutvg4.png]]
          - 地址域为 11 位，由 7 位的设备地址 + 4 位的端点地址组成
        - **帧号域**
          - **11 位**
            • 主机每发出一个帧，帧号都会自动加 1（全速和低速设备 1ms 发出一帧，高速设备 0.125ms 发出一帧）
            • 当帧号达到 0x7FF 的时候，将清零帧号重新计数
            • 仅在每个帧的帧首才传输一次 SOF 包
      - **数据域（只存在于数据包中）**
        - 各传输类型的数据域最大长度（表 2-10）：控制 64；批量 HS 512 / FS 64；中断 HS 1024 / FS 64 / LS 8；同步 HS 1024 / FS 1023
          ![[99-附件/USB/0u1kku10dbpq1rtelqduhq55gb.png]]
        - 根据传输类型的不同，数据域的数据长度从 0-1024 字节不等。
          - **传输类型**
            - **控制传输**
              - **控制传输：非周期性传输，用于命令和状态的传输**
                • 每个 USB 设备都必须有控制端点，支持控制传输来进行命令和状态的传输。 USB 主机驱动程序将通过控制传输与 USB 设备的控制端点通信，完成 USB 设备的枚举和配置
                • 控制传输是双向的传输，必须有 IN 和 OUT 两个方向上的特定端点号的控制端点来完成两个方向上的控制传输
                - SETUP 阶段的事务格式（图 2-26）：SETUP 令牌（DATA0）→ 数据 → ACK 握手
                  ![[99-附件/USB/4o8aeh67oo3abuk1tpfoi076u4.png]]
                - 控制传输至少包含两个事务阶段：设置（SETUP）阶段和状态（Status）阶段。控制传输还可以选择性地在 SETUP 阶段和状态阶段之间包含一个数据（DATA）阶段。在 SETUP 阶段，使用一个 SETUP 事务来向某个函数单元（设备）的控制端点传输信息。 SETUP 事务的格式与 OUT 事务相似，但使用的是 SETUP PID而不是 OUT PID。图展示了 SETUP 阶段的事务格式。在SETUP 事务中，数据字段总是使用 DATA0 PID。
                  接收 SETUP 的函数单元（设备）必须接收 SETUP 数据并以 ACK 作为响应；如果数据损坏，则丢弃这些数据并且不返回任何握手信号。
                  在控制传输中，如果存在数据阶段，则这一阶段由一个或多个 IN 或 OUT 事务组成，并遵循与批量传输相同的协议规则。数据阶段中的所有事务都必须在同一方向上（即全部为 IN 或全部为 OUT）。数据阶段要发送的数据量及其方向在 SETUP 阶段指定。如果数据量超过了预先协商的数据包大小，则数据将在多个事务（IN 或 OUT）中发送，每个事务携带最大数据包大小。剩余的数据将在最后一个事务中作为剩余数据发送。
                  控制传输的状态阶段是序列中的最后一个事务。状态阶段的事务遵循与批量传输相同的协议序列。
                  对于以高速运行的设备，状态阶段还包括 PING 协议。状态阶段通过改变与前一阶段的数据流方向来界定，并且总是使用 DATA1 PID。例如，如果数据阶段由 OUT 事务组成，则状态阶段是一个单独的 IN 事务。如果控制传输没有数据阶段，则它由一个 SETUP 阶段后跟一个 IN 事务的状态阶段组成
                - 控制传输读写序列（图 2-27）：Setup 阶段 → Data 阶段（写用 OUT、读用 IN）→ Status 阶段
                  ![[99-附件/USB/5mbejrb1rk3f0dofbqj8f9f96q.png]]
            - **批量传输**
              - 批量传输：非周期性传输，用于批量传输的通信，数据可以占用任意带宽
                • 批量传输适用于那些需要大数据量的传输，但是对实时性、延迟性和带宽没有严格要求。批量传输可以占用任意可用的数据带宽
                • 批量传输是单向的，可以用单向的批量传输端点来实现某个方向的批量传输
                - 批量传输的 IN / OUT 事务流程：含 ACK / NAK / STALL 握手与错误处理，PING / NYET 仅高速使用
                  ![[99-附件/USB/1rknupp0mci26t5ibbe1cj4cs9.png]]
                - 批量传输的特点是通过错误检测和重试机制，确保主机与函数单元（设备）之间数据的无错传输。
                  批量传输采用如图所示的三阶段事务，包括令牌包、数据包和握手包。在某些流控制和暂停条件下，数据阶段可能会被握手包替换，从而形成一个不传输数据的两阶段事务。 PING 和 NYET 包仅能与高速运行的设备一起使用。
                  当主机准备好接收批量数据时，它会发出一个 IN 令牌。函数单元（设备）通过返回一个数据包来响应，或者如果它无法返回数据，则返回一个 NAK 或 STALL 握手信号。 NAK 表示设备暂时无法返回数据，而 STALL 表示端点被永久停止，需要 USB 系统软件进行干预。如果主机接收到有效的数据包，它会以 ACK握手信号作为响应。如果主机在接收数据时检测到错误，则不会向设备返回任何握手包。
                  当主机准备好传输批量数据时，它首先发出一个 OUT 令牌包，后跟一个数据包。如果函数单元（设备）无误地接收到数据，它将返回 ACK、 NAK、 STALL、 NYET 握手信号之一。
                  如果数据包在接收时存在 CRC（循环冗余校验）或位填充错误，则不会返回任何握手信号
            - **中断传输**
              - **中断传输：周期性传输，具有低频率，允许有限延迟的通信**
                • 中断传输用于那些频率不高，但对周期有一定要求的数据传输。具有保证的带宽，并能在下个周期对先前错误的传输进行重传
                • 中断传输总是单向的，可以用单向的中断端点来实现某个方向上的中断传输
                - 中断传输事务流程（图 2-28）：IN / OUT 令牌 + 数据 + 握手
                  ![[99-附件/USB/6k8msb64p5u68vc995fdk2hp8t.png]]
                - 中断传输可能包括 IN 或 OUT 事务的传输。在接收到 IN 令牌后，一个函数单元（设备）可以返回数据、 NAK 或 STALL。如果端点没有新的中断信息要返回（即没有待处理的中断），则在数据阶段该函数单元（设备）会返回一个 NAK 握手信号；如果为中断端点设置了 Halt（暂停）功能，则该函数单元（设备）将返回一个 STALL 握手信号；如果有一个待处理的中断，该函数单元（设备）将中断信息作为数据包返回。主机在接收到数据包后，如果数据无误，则发出 ACK（确认）握手信号；如果数据包接收时出错，则不返回任何握手信号。
            - **同步传输**
              - 同步传输：周期性传输，它是持续的传输，用于传输与时效相关的信息，并且在数据中保存时间戳的信息
                • 同步传输用于传输那些需要保证带宽，并且不能忍受延迟的信息。整个带宽都将用于保证同步传输的数据完整，并且不支持出错重传
                • 同步传输总是单向的，可以使用单向的同步端点来实现某个方向上的同步传输
                - 同步传输事务流程（图 2-29）：只有令牌阶段和数据阶段，没有握手阶段
                  ![[99-附件/USB/3rmu783644qgo31f6s3b75s759.png]]
                - 同步传输包括令牌阶段和数据阶段，但没有握手阶段。主机发出一个 IN 或 OUT 令牌，随后就是数据阶段。同步传输不支持握手阶段或重试功能。
      - **CRC域**
        - CRC 计算公式（图 2-16）：Token CRC 为 5 位，G(X)=X^5+X^2+1；Data CRC 为 16 位，G(X)=X^16+X^15+X^2+1
          ![[99-附件/USB/646s9rvqom3u49aikjvd6cd0i6.png]]
        - 循环冗余校验（CRC）用于保护令牌和数据包中的所有非 PID 字段。在此上下文中，这些字段被视为受保护字段。在比特填充操作之前，所有 CRC 都是在发送器的各自字段上生成的。同样，在接收器中，
          CRC 是在移除了填充位之后进行解码的。令牌和数据包的 CRC 提供了对所有单比特和双比特错误的 100%
          覆盖。 CRC 失败表示一个或多个受保护字段已损坏，导致接收器忽略这些字段，并且在大多数情况下，
          忽略整个数据包。
          CRC 分为两种，如图 2-16，一种是 Token CRC，用于计算地址域（令牌包）和帧号域（SOF 包）的
          CRC，另一种是 Data CRC，用于计算数据域数据（数据包）的 CRC。
          握手包只有 PID 域，所以没有 CRC
    - **Packet 的类型**
      令牌包：PID 后面跟的是地址、端点号或帧号，然后 CRC5，没有 Data 域。
      数据包：PID 后面直接跟 Data 域，Data 后面跟 CRC16，然后 EOP。
      握手包：只有 PID，没有 Data，也没有 CRC。
      - PID 类型表（表 2-9）：令牌类 / 数据类 / 握手类 / 特殊类及各自的 PID[3:0] 编码
        ![[99-附件/USB/72pkkmaoioso9dekl5nv76mnav.png]]
      - **令牌包**
        - **普通令牌包**
          PID + 地址 + CRC
          PID： IN、 OUT、 SETUP 令牌
          地址： 7 位的设备地址和 4 位的端点号组成
          CRC：这里是仅对地址域计算
          ![[99-附件/USB/672dvdqkqrinivce7aae4t75im.png]]
          - SETUP 令牌包数据（图 2-18）：SYNC + SETUP(0xB4) + ADDR + ENDP + CRC5 + EOP
            ![[99-附件/USB/271m0f7hpc4hd0matqmplj0ig2.png]]
        - **SOF（特殊令牌包）**
          PID + 帧号 + CRC
          PID： SOF 令牌

      - **握手包**
        - **握手包的组成为：PID**
          PID： ACK、 NAK、 STALL、 NYET（握手包没有 CRC）
          • ACK：表示正确接收数据，并且有足够的空间来容纳数据。主机和设备都可以用 ACK 来确认，而 NAK、 STALL、 NYET 只能设备返回，主机不能使用这些握手包。
          • NAK：表示没有数据需要返回，或者数据正确接收但是没有足够的空间来容忍它们。当主机收到 NAK 时，知道设备还未准备好，主机会在以后合适的时机进行重新传输。
          • STALL：表示设备无法执行这个请求，或者端点已经被挂起，它表示一种错误的状态。设备返回 STALL 后，需要主机进行干预才能解除这种 STALL 状态。
          • NYET：只在 USB2.0 的高速设备输出事务中使用，表示设备本次数据成功接收，但是没有足够的空间来接收下一次数据。主机在下一次输出数据时，将先使用 PING 令牌包来试探设备是否有空间接收数据，以避免不必要的带宽浪费。

      - USB 使用的差分传输模式，即两条数据线 D+和 D-，首先明确几个概念：
        差分信号 1： D+ > VOH 且 D- < VOL
        差分信号 0： D- > VOH 且 D+ < VOL
        IDLE 状态： J 状态
        复位信号： D+ and D- < VOL for >= 10ms。
        挂起信号： USB 主机 3ms 内不发送任何信号（3ms 以上的 IDLE 状态）。
        唤醒信号： K 状态持续 20ms 以上，并以 2 个位时间的 EOP 信号结尾。
        注意： VOH： 2.8V(min)， VOL： 0.3V(max)
## 数据传输方式
- USB 采用轮询的广播机制传输数据，所有的传输都由主机发起，任何时刻整个 USB 体系内仅允许一个数据包的传输，即不同物理传输线上看到的数据包都是同一被广播的数据包。
## USB简介
- USB 是一种支持热插拔的高速串行传输总线，它使用差分信号来传输数据，最高速度可达 480 Mbps（USB 2.0 高速）。USB 支持“总线供电”和“自供电”两种供电模式。
- **USB 体系包括“主机”、“设备”以及“物理连接”三个部分。**
  - **主机：**
    主机是一个提供USB 接口及接口管理能力的硬件、软件及固件的复合体，可以是 PC，也可以是 OTG 设备，一个 USB 系统中仅有一个 USB 主机；设备包括 USB 功能设备和 USB HUB，最多支持127 个设备；物理连接即指的是 USB 的传输线。在 USB 2.0 系统中，要求使用屏蔽的双绞线。
    - **什么是OTG设备？**
      - OTG设备，全称 USB On-The-Go 设备，是指支持 USB OTG 补充规范的设备。它的核心能力是：既能当 USB 外设，也能在需要时当 USB 主机。典型代表是手机、平板、相机等便携设备。
        传统 USB 是“PC 当主机，外设当从机”。OTG 的出现，是为了让手机这类设备也能直接接 U 盘、键盘、鼠标、游戏手柄、打印机等，而不必经过 PC。
      - **1. 物理层：ID 引脚决定初始角色**
        OTG 常用 Mini-AB / Micro-AB 插座，比普通 USB 多一个 ID 引脚：
        ID 引脚状态	角色	说明
        ID 接地	A 设备	默认主机，负责提供 VBUS 5V
        ID 悬空	B 设备	默认外设，消耗 VBUS
        所以：
        普通 Micro-B 数据线：ID 悬空，手机是外设。
        OTG 转接线：ID 接地，手机变成 A 设备主机，可以接 U 盘。
      - **2. OTG 的关键协议**
        SRP，会话请求协议：B 设备可以请求 A 设备打开 VBUS，开始会话。
        HNP，主机交换协议：允许 A、B 设备交换数据角色。原来当外设的 B 设备可以变成主机，原来当主机的 A 设备变成外设。
        注意：OTG 中 A 设备通常仍负责供电，HNP 主要交换的是数据角色。
        ADP，附件检测协议：用于检测连接的是 OTG 设备还是普通外设，较新规范引入。
      - **3. OTG 设备 ≠ 普通 USB 外设**
        严格来说：
        OTG 设备：支持 OTG 规范，具备双角色能力。
        U 盘、键盘、鼠标：普通 USB 外设，不是 OTG 设备。
        日常说的“OTG 设备”，有时泛指“支持 OTG 的手机/平板”，或“通过 OTG 连接的外设”。
      - **4. 和 USB Type-C 的关系**
        现在很多手机用 Type-C，不再用 ID 引脚，而是用 CC 引脚协商角色：
        DFP：下行端口，类似主机。
        UFP：上行端口，类似外设。
        DRP：双角色端口，可在 DFP/UFP 间切换。
        所以今天说“OTG”，很多时候其实是 Type-C 的双角色功能，概念被泛化了。
