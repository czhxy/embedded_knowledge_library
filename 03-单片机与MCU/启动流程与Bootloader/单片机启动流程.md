## 从上电到main函数之间经历了什么？
- **1. 设置栈大小、堆大小**
  - Stack_Size      EQU     0x00000400（1KB）
  - Heap_Size       EQU     0x00000200（512B）
- **2. 硬件自动设置栈指针**
  - __Vectors       DCD     __initial_sp               ; Top of Stack
- **3. 将 Reset_Handler 装入 PC**
- **4. 进入 SystemInit()**
  - 1. 开启 FPU（浮点运算单元）这一步的作用是：告诉内核"FPU 可以用，别报异常"。否则 FreeRTOS 做上下文切换时碰到浮点寄存器会直接 HardFault
  - **2. 时钟系统复位到默认状态**
      这 6 行操作是把 RCC（时钟控制器）所有寄存器打回出厂默认值，消除上电不确定状态。
     RCC->CR |= (uint32_t)0x00000001;
     HSION bit 置 1 → 开启内部高速时钟 HSI（16MHz RC 振荡器），保证 CPU 有基本时钟源可用。
     RCC->CFGR = 0x00000000;
     清除时钟配置寄存器 → HSI 作为系统时钟、AHB 不分频、APB1/APB2 不分频。
     RCC->CR &= (uint32_t)0xFEF6FFFF;
      - 第 16 位清零 → 关闭 HSEON（外部高速时钟）
      - 第 19 位清零 → 关闭 CSSON（时钟安全系统）
      - 第 24 位清零 → 关闭 PLLON（锁相环）
     RCC->PLLCFGR = 0x24003010;
     PLL 配置寄存器写默认值（PLLM=16, PLLN=192, PLLP=2, PLLQ=4, PLL 源 = HSI）。
     RCC->CR &= (uint32_t)0xFFFBFFFF;
     HSEBYP 清零（不使用外部时钟旁路模式）。
     RCC->CIR = 0x00000000;
     清零时钟中断寄存器 → 关闭所有和时钟相关的中断（HSE就绪中断、PLL就绪中断等），避免初始化过程中被无关中断干扰。
  - **3. 外部存储器控制器初始化（条件编译）**
     #if defined(DATA_IN_ExtSRAM) || defined(DATA_IN_ExtSDRAM)
          SystemInit_ExtMemCtl();
      #endif
     只有定义了 DATA_IN_ExtSRAM 或 DATA_IN_ExtSDRAM 宏（在 system_stm32xxx.c 中定义）时才编译。当程序数据段需要跑在外部SRAM/SDRAM 上时，预先初始化 FSMC/FMC 控制器
  - **4. 设置系统时钟**
      SetSysClock();
      这是核心。在 system_stm32f4xx.c 中实现，流程为：
      SetSysClock()
        │
        ├─ 开启 HSE，等待就绪（超时则 fallback 到 HSI）
        │
        ├─ 配置 PLL（根据 HSE_VALUE 和目标 SYSCLK 计算 M/N/P/Q 分频比）
        │    通常：PLL = HSE / M * N / P
        │
        ├─ 开启 PLL，等待锁定
        │
        ├─ 配置 FLASH 等待周期（高频率需要更多等待周期）
        │    - ≤ 30MHz: 0WS
        │    - ≤ 60MHz: 1WS
        │    - ≤ 90MHz: 2WS
        │    - ≤ 120MHz: 3WS
        │    - ≤ 150MHz: 4WS
        │    - ≤ 168MHz: 5WS  ...
        │
        ├─ 配置 AHB/APB1/APB2 预分频器
        │    APB1 最大 45MHz（通常 /4）
        │    APB2 最大 90MHz（通常 /2）
        │
        └─ 切换系统时钟源到 PLL
    - STM32 时钟树——从 F1 的强制分频到 F4 的三级 PLL
      - STM32F1 的强制 /2：F103 中RCC_CFGR.PLLSRC=0时，HSI（8MHz）必须固定 2 分频为 4MHz 后才能进入 PLL。
        这是硬件设计，没有配置位可以绕过。原因是 F1 的 VCO（压控振荡器）有最佳输入频率范围，4MHz 是设计甜点；同时省掉了可配置分频器，降低硅片面积。
        HSE 的灵活性：F1 中 HSE 可以通过PLLSRC=1, PLLXTPRE=0直通进 PLL，也可以通过PLLSRC=1, PLLXTPRE=1,除2 后进 PLL。这是因为 HSE 频率范围宽（4~16MHz），如果用户接 16MHz 晶振直接 ×16 = 256MHz 会超限，所以给了可选 /2 的退路（16/2 × 9 = 72MHz）
        F1 最大频率限制：HSI/2 = 4MHz，最大倍频 ×16 = 64MHz，到不了 F103 的 72MHz 上限。因此F103 想跑满 72MHz 必须用 HSE 不分频进 PLL 再 ×9
      - **F4 的三级 PLL 架构：**
        M（预分频）→ N（倍频）→ P（后分频）
        SYSCLK = (HSE / PLL_M) × PLL_N / PLL_P
        PLL_M（2~63）：把晶振降到 1~2MHz 进 VCO。
        PLL_N（50~432）：VCO 核心倍频，最大 432，但受 VCO 输出 100~432MHz 范围约束。
        PLL_P（2/4/6/8）：VCO 输出再分频给 CPU。
        典型 168MHz 配置：HSE=8MHz → M=4（2MHz）→ N=168（336MHz VCO）→ P=2（168MHz SYSCLK），同时 Q=7 给 USB 48MHz。
        - - M 预分频的原因：PLL 核心是 PFD（鉴相器），它比较参考频率和 VCO/N 反馈频率的边沿。PFD 的最佳工作频率在 **1~2MHz**，太高会导致边沿间隔太短、比较器来不及响应、抖动变大、环路不稳定。
          - N 倍频的原因：VCO 是模拟电路，有物理频率范围限制（F4 的 VCO 为 100~432MHz）。太低不起振/相位噪声差，太高波形畸变。N 的作用是在 VCO 允许范围内，把 PFD 的低频升到 VCO 能输出的高频。
          - P 后分频的原因：VCO 输出 ≠ CPU 需要的频率。VCO 在 336MHz 附近的相位噪声通常比 168MHz 好（高频 VCO 的 Q 值更高），所以让 VCO 跑在较高的 336MHz，再用 P=2 降到 CPU 需要的 168MHz，兼顾了相位噪声和功耗。
        - // STM32F103 标准库：8MHz HSE × 9 = 72MHz
          RCC_PLLConfig(RCC_PLLSource_HSE_Div1, RCC_PLLMul_9);
          // STM32F407 HAL：8MHz → 168MHz
          RCC_OscInitStruct.PLL.PLLM = 4;      // 8MHz / 4 = 2MHz (VCO输入)
          RCC_OscInitStruct.PLL.PLLN = 168;    // 2MHz × 168 = 336MHz (VCO输出)
          RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV2;  // 336 / 2 = 168MHz (SYSCLK)
          RCC_OscInitStruct.PLL.PLLQ = 7;      // 336 / 7 = 48MHz (USB)
  - **5. 向量表重定位**
      #ifdef VECT_TAB_SRAM
        SCB->VTOR = SRAM_BASE | VECT_TAB_OFFSET;
      #else
        SCB->VTOR = FLASH_BASE | VECT_TAB_OFFSET;
      #endif
  - **6. __main，C 库初始化**
